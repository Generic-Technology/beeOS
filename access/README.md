# access — 对外接入面

> **状态：骨架。实现未落地。** 设计稿见 [agent-integration.md](agent-integration.md)。
> 这个目录现在只声明边界，不提供对外能力——**先定契约，再填实现**。

## 这是什么

**接入面 = 谁调 BeeOS、凭什么调、调完怎么算。**

它是编排层之上的**门面**：不装盒子，也不装机制，
是同一套 `runtime/` 与编排层对外说话的地方。

## 为什么单独立一个目录

仓库里已经有两个平级的「面」——`kanban/`（盯运行时）和
`workshop/`（体检台）。接入面是第三个，但**约束方向相反**：

| | 看板 / 工作台 | 接入面 |
|---|---|---|
| 给谁看 | 人 | 程序（外部 agent、脚本、别的系统） |
| 回答 | 「现在哪儿坏了」 | 「我这次调用成没成、下一跳该做什么」 |
| 形状稳不稳 | 不稳（跟着页面改） | **要稳**：对外发布之后难改 |
| 能不能写 | 不能 | 能——但**写只发生在盒内 op 里** |
| 方向 | 人 → 机器 | 机器 → 机器 |

**为什么不塞进 `kanban/`**：`kanban/web.py` 是给前端画页面的，
它的返回形状跟着页面走。接入面的形状**必须稳**——
两个诉求方向相反，混在一起就是「看板改 UI 牵连对外契约」，
或者「对外契约要稳的要求拖慢看板迭代」。

**为什么不是 `agent` 主题目录**：agent 只是调用方的一种。
按调用方类型建目录，等于把一层的东西按「谁在调」重排——
来个非 agent 的调用方，这目录名就不准了。
按**层**放，才对得上仓库现在的结构（`core` 协议 / `runtime` 执行 /
`boxes` 业务 + 平级的面）。

## 装什么 / 不装什么

| 装 | 不装 |
|---|---|
| 对外契约的**版本化定义**（动作清单、请求 / 响应形状、错误语义） | 业务判据、盒子内部形状 |
| **任务服务**：投料 / 过闸 / 查履约 / 回答升级 / 链计划（唯一真源） | 执行机制（那是 `runtime/` 的事） |
| **调用方身份与授权**（`decided_by` 的真源） | 模型 provider（那是 `runtime/llm.py` 的事） |
| **幂等键语义** | 幂等台账的持久化实现（落 `runtime/store.py`） |
| **适配器**：CLI / HTTP / MCP | 目标对象的写权限闸（那是盒内 op 的事） |

## 对外动作清单

契约**只有一份**，三个适配器都调它：

| 动作 | 语义 |
|---|---|
| `list_boxes` | 有哪些盒、每只盒能接什么任务 |
| `box_manifest` | 一只盒的完整自描述（输入 / 产出 / 判据 / 例外） |
| `check_intake` | **只过契约闸，不执行**——投料前先验形状 |
| `submit_task` | 提交一次履约，返回 `task_run_id` + `status=queued` |
| `get_run` | 查一次履约的状态、产出、验收结论、执行轨迹 |
| `submit_decision` | 回答一次升级（**身份由认证确定**，不由请求体来） |
| `get_chain` | 看链历史（只读） |
| `advance_chain` | 驱动链前进（编排层职责） |

`check_intake` 单独暴露是有意的：它让调用方在**不产生履约**的前提下
知道自己投错了没有。

## 目录布局（拟新增，**都还不存在**）

| 文件 | 职责 |
|---|---|
| `contract.py` | 对外契约的版本化定义：动作、请求 / 响应形状、错误语义 |
| `service.py` | 任务服务：投料 / 过闸 / 查履约 / 答升级 / 链计划（**唯一真源**） |
| `identity.py` | 调用方身份与授权 |
| `idempotency.py` | 幂等键语义（同键同载荷 / 同键不同载荷 / 在途 / 终态） |
| `plan.py` | 链级执行计划对象（声明投影 + 执行状态） |
| `cli.py` | 适配器：CLI（Codex / Claude Code 这类有 shell 的） |
| `http.py` | 适配器：HTTP |
| `mcp.py` | 适配器：MCP（豆包 / 千问办公 这类） |

**不预建空壳模块**：仓里有一条纪律——
「**不登记没人能执行的插件类型**」（`docs/component-plugin-model.md` §1.3.3）。
声明一个还没实现的动作，比不声明更坏：**读的人以为它能用**。
所以这些文件等到各自有实现了再建。

## 六条纪律

1. **一份实现，多个适配器**——CLI / HTTP / MCP 共用任务服务，
   不许任何适配器自己抄一份调用逻辑。
2. **契约版本化**——变更走新增版本，不原地改。
3. **形状来自盒子**——产出形状由盒子的 `result_schema` 决定，
   **适配器不许知道具体某只盒子的产出字段**。
4. **身份与授权先于写能力**——授权必须与写能力同一批上线
   （先开门后装锁 = 没装）。
5. **写只发生在盒内 op 里**——目标对象的写凭证**不进调用方侧**，
   那是唯一真拦得住绕过的边界。
6. **幂等台账与持久化执行一起设计**——没有「先落盘」，
   外部写成功而服务中断时就无从核对目标状态。
