# 获客实验盒（shopify_acquisition_experiment_box）

> 设计并**真的投放**一轮获客实验：场景、落地页、变更项、成本上限、起止时间、停止条件、归因方式。

## 「直接投放」到底指什么

首轮实验是**自然渠道内容实验**：改的是店铺自己的落地页内容
（标题 / 正文 / SEO 标题与描述 / 标签）。

自然渠道没有「投放 API」——**唯一能被自动化的投放，就是改自己的页面**。
所以本盒的职责是：**自己把内容改上去**，不再交一份施工单等人手动改。

## 两道闸都要开才写

| 闸 | 在哪 | 为什么 |
| --- | --- | --- |
| **逐次意图** | 投料里的 `apply: true` | 看板示例投料、交接链路、任何自动发起的履约都不带它 |
| **进程级写闸** | `SHOPIFY_ALLOW_WRITES=1` | 「配了写权限 token」和「允许写」是**两件不同的事** |

只靠环境变量那一道不够：看板的示例投料和自动链路都带着环境变量跑，
那样一次点错就是改在营业中的页面上——**改错了不会报错**。

**写闸关着的时候**：本盒只出方案（起草内容照样留在记录里），
`applied = False`，判据 `applied eq True` 因此判红 → 整轮被拒 → 不进档案。

**「出方案但没落笔」不算交付**——这是「直接投放」的判据。

## 还有两道

- **字段白名单**：只写 `title` / `descriptionHtml` / `seo.title` /
  `seo.description` / `tags`。价格、库存、变体、发布状态**不在白名单**——
  那些是「改错了要赔钱」的字段。
- **一次一个落地页**：一轮只改一个变量，同时改两处结果不可归因。

## 改前基线

写之前先读一遍旧字段值，存进产出（`baseline_fields`）。
**没有基线就没法回滚、没法对照**。

## 模型起草的内容也要校验

标题非空且不过长、正文非空、SEO 标题 ≤ 70 字符、SEO 描述 ≤ 160 字符、标签非空。
草稿不合格 → 没有草稿 → 不写 → 判据判红。

## 归因方式是**一等字段**

`utm` / `landing_page_time_window` / `none`。

自然搜索**没有 UTM**——把 UTM 当唯一归因方式，
等于让 SEO / AI 引荐这一类渠道永远归因不到。

## 首轮不判 ROAS

样本太小，转化率波动比信号大。ROAS 是辅助指标，不是首轮判据。

首轮判据是**方案完整性 + 真的落笔**：场景、落地页、变更项、成本上限、
起止时间、停止条件、归因方式齐全，且 `applied`。

## 成熟度：skeleton

腿（起草 + 写入 + 记录）实现了，但**还没在真店上跑过**——
写权限还没批，也没有一次真的写入记录。

**没落笔时的样子**：产出的方案字段**缺席**、标志位全 false，
判据因此全红 → 整轮被拒 → 不进档案。
