# 获客诊断盒（shopify_traffic_diagnosis_box）

> 判断这一轮流量**断在哪一段**，给出一个主问题假设、一个目标客群、一个优先渠道。

## 断点分四段

| 断点 | 现象 | 下一轮该做什么 |
| --- | --- | --- |
| `no_impression` | 没有曝光 | 分发 / SEO / 内容 / 广告没启动 |
| `no_click` | 有曝光没点击 | 素材 / 受众 / 卖点不匹配 |
| `no_session` | 有点击没 session | 链接 / 追踪 / 落地页有问题 |
| `no_product_view` | 有 session 没商品浏览 | 落地页与商品承接有问题 |

分不出单一断点时，写 `no_single_bottleneck`——**别装作知道**。

## 判定走模型

四段漏斗里，**曝光和点击没有数据源**：Shopify 的 `sessions` schema 只给 session 侧。
所以「断在哪一段」规则算不出来，得让模型读快照说人话。

**但模型会编**，所以它的产出必须被机械校验：

| 模型说 | 校验 | 不通过怎么办 |
| --- | --- | --- |
| `bottleneck_stage` | 必须在四段（+「分不出单一断点」）里 | 整份结论作废 |
| `bottleneck_evidence` | 每一条都必须是快照里**真实存在的指标名** | 整份结论作废 |
| `hypothesis` | 只能有一个，不能空 | 整份结论作废 |
| `unknowns` | 「分不出单一断点」时必须非空 | 整份结论作废 |

作废时**带反馈重试一次**（把「上次哪一条不合格」写回提示词）。
只重试一次——再错就是这件事这轮做不成。

**模型不产出任何数字**：它只引用指标名。数值由快照盒算，
模型报了也不作数（同一个量只能有一个来源）。

## 结论必须带证据引用

`bottleneck_evidence` 里每一条都要指得到快照里的**某个指标名**——
「流量少」不是证据，「qualified_sessions = 148」才是。

## 未知项必须写出来

分不出来的段就说是分不出来，写进 `unknowns`。
**判据只判「如实」，不判「假设对不对」**：假设对不对要等下一轮复测。

## 成熟度：live

**真跑过**（真快照 + 真模型 + 真校验）：2026-11-16 起在真店上跑过整条链，
判据全绿、结论进了档案。

**模型两次都不合格时怎么办**：产出一份**没有结论**的诊断
（结论字段缺席，标志位全 false）→ 判据全红 → 整轮被拒 → 不进档案。
**那是「这一轮做不成」，不是「要人拍板」**——所以合同例外写的是
`no_deliver`（明确的不交付），不是 `escalate`：
没有结论可放行，挂一条等人判定的账只会攒下没人答得了的票。
